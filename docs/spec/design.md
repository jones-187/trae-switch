## 4. 技术实现细节

### 4.1 后端实现

1. **App结构体修改**：
   - 添加`lanMode bool`字段
   - 实现`SetLanMode`和`IsLanMode`方法

2. **Proxy服务器修改**：
   - 添加`LanListenAddr = "0.0.0.0"`常量
   - 修改服务器初始化逻辑，支持动态监听地址

3. **GetStatus方法修改**：
   - 在返回值中添加`lanMode`字段

4. **SetLanMode方法设计**：
   - 检查当前代理状态，保存状态
   - 如果代理已运行，停止代理
   - 设置新的lanMode值
   - 创建新的proxyServer实例，使用正确的监听地址
   - 如果之前代理是运行状态，重新启动代理

### 4.2 前端实现

1. **界面修改**：
   - 在系统配置模块添加"监听局域网"开关
   - 使用`Switch`组件实现开关效果
   - 显示当前监听模式状态（开启/关闭）

2. **交互逻辑**：
   - 点击开关时切换lanMode状态
   - 调用后端API设置lanMode
   - 处理API调用结果，显示相应提示

### 4.3 数据流

1. **设置lanMode流程**：
   - 前端点击开关 → 调用SetLanMode API → 后端检查代理状态并保存 → 停止代理（如果在运行） → 设置新的lanMode值 → 创建新的proxyServer实例 → 重启代理（如果之前在运行） → 返回结果 → 前端更新开关状态

2. **获取lanMode流程**：
   - 前端页面加载 → 调用GetStatus API → 后端返回lanMode状态（包含在GetStatus返回值中） → 前端更新开关状态

## 5. 配置管理

| 配置项 | 类型 | 默认值 | 描述 |
|--------|------|--------|------|
| lanMode | bool | false | 局域网监听模式状态 |
| listenAddr | string | "127.0.0.1" | 代理服务器监听地址（根据lanMode动态调整） |
| listenPort | int | 443 | 代理服务器监听端口 |

## 6. 错误处理

| 错误类型 | 错误码 | 描述 | 处理方式 |
|----------|--------|------|----------|
| 代理重启失败 | 500 | 停止或启动代理时发生错误 | 返回错误信息，保持原有状态 |
| 参数错误 | 400 | 传入的参数无效 | 返回错误信息，不执行操作 |
| 网络错误 | 503 | 网络连接异常 | 返回错误信息，建议检查网络 |

## 7. 性能考虑

- **内存使用**：添加一个bool字段，内存开销可忽略
- **CPU使用**：代理重启操作仅在状态切换时执行，对CPU影响很小
- **网络影响**：监听0.0.0.0可能会接收到更多网络请求，但影响可控

## 8. 安全考虑

- **默认关闭**：局域网监听功能默认关闭，减少安全风险
- **防火墙**：建议用户在开启时确保防火墙设置正确
- **网络环境**：建议在安全的局域网环境中使用

## 9. 兼容性考虑

- **操作系统**：支持所有主流操作系统（Windows, macOS, Linux）
- **网络环境**：支持各种局域网拓扑结构
- **浏览器**：前端界面兼容主流浏览器

## 10. 未来扩展

## 11. 代码生成规范

### 11.1 业务目标
实现局域网监听功能，使其他设备能够通过局域网访问本地代理服务。

### 11.2 上下文依赖
- **后端**：
  - `app.go`：App结构体，包含核心应用逻辑
  - `internal/proxy/proxy.go`：代理服务器实现
- **前端**：
  - `frontend/src/App.svelte`：主应用组件
  - `frontend/src/components/ui/Switch.svelte`：开关组件

### 11.3 命名规范
- **Go代码**：
  - 变量名：驼峰命名法（如`lanMode`）
  - 方法名：驼峰命名法（如`SetLanMode`）
  - 常量名：大写字母加下划线（如`LanListenAddr`）
- **Svelte代码**：
  - 变量名：驼峰命名法（如`lanMode`）
  - 函数名：驼峰命名法（如`toggleLanMode`）

### 11.4 代码风格
- **Go代码**：
  - 缩进：使用4个空格
  - 代码行长度：不超过120个字符
  - 空行：适当使用空行分隔逻辑块
- **Svelte代码**：
  - 缩进：使用4个空格
  - 代码行长度：不超过120个字符

### 11.5 注释规范
- 结构体和方法添加适当的注释
- 关键逻辑添加注释说明
- 错误处理添加注释说明

### 11.6 错误处理
- **后端**：
  - 使用错误返回值，不使用panic
  - 错误信息清晰明了，包含具体错误原因
  - 关键操作处添加错误日志
- **前端**：
  - 使用try-catch捕获异常
  - 显示友好的错误提示给用户
  - 错误信息应包含具体原因和解决方案

### 11.7 约束边界
- **文件大小**：单个文件不超过500行
- **方法行数**：单个方法不超过50行
- **嵌套层级**：不超过3层嵌套
- **依赖注入**：合理控制依赖数量

### 11.8 安全约束
- 网络安全：默认关闭局域网监听功能
- 权限检查：确保管理员权限检查逻辑完整
- 错误处理：所有错误必须有明确的错误信息

### 11.9 性能约束
- 内存使用：添加的字段和方法不应显著增加内存使用
- CPU使用：代理重启操作仅在状态切换时执行
- 网络影响：监听0.0.0.0可能会接收到更多网络请求，但影响可控
