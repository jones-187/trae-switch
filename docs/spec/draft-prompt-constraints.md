实现局域网监听功能，使其他设备能够通过局域网访问本地代理服务。

## 3. 输出格式

### 3.1 代码风格
- **Go代码**：
  - 缩进：使用4个空格
  - 代码行长度：不超过120个字符
  - 命名规范：
    - 变量名：驼峰命名法（如`lanMode`）
    - 方法名：驼峰命名法（如`SetLanMode`）
    - 常量名：大写字母加下划线（如`LanListenAddr`）
  - 注释：为结构体和方法添加适当的注释

- **Svelte代码**：
  - 缩进：使用4个空格
  - 代码行长度：不超过120个字符
  - 命名规范：
    - 变量名：驼峰命名法（如`lanMode`）
    - 函数名：驼峰命名法（如`toggleLanMode`）
  - 注释：为关键逻辑添加注释

### 3.2 代码结构
- **后端**：
  - 遵循现有的代码结构和命名约定
  - 保持方法简洁，单一职责
  - 错误处理：使用错误返回值，不使用panic
  - 日志记录：在关键操作处添加适当的日志

- **前端**：
  - 遵循现有的组件结构和命名约定
  - 保持组件简洁，单一职责
  - 错误处理：使用try-catch捕获异常
  - 状态管理：使用Svelte的响应式变量

## 4. 约束边界

### 4.1 防腐败底线
- **文件大小**：单个文件不超过500行
- **方法行数**：单个方法不超过50行
- **嵌套层级**：不超过3层嵌套
- **依赖注入**：合理控制依赖数量

### 4.2 安全约束
- 网络安全：默认关闭局域网监听功能
- 权限检查：确保管理员权限检查逻辑完整
- 错误处理：所有错误必须有明确的错误信息

### 4.3 性能约束
- 内存使用：添加的字段和方法不应显著增加内存使用
- CPU使用：代理重启操作仅在状态切换时执行
- 网络影响：监听0.0.0.0可能会接收到更多网络请求，但影响可控

## 5. 错误处理

### 5.1 全局异常处理
- **后端**：
  - 使用错误返回值，不使用panic
  - 错误信息清晰明了，包含具体错误原因
  - 关键操作处添加错误日志

- **前端**：
  - 使用try-catch捕获异常
  - 显示友好的错误提示给用户
  - 错误信息应包含具体原因和解决方案

### 5.2 规范错误码使用
- 遵循现有的错误处理模式
- 错误信息应包含具体的错误原因
- 对于常见错误，提供明确的解决方案
